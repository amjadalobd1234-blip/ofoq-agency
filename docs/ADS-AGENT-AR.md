# وكيل الإعلانات (Ads Agent) — الخامس من الوكلاء الخمسة

## ماذا يفعل؟

وكيل الإعلانات يحوّل **أهداف العميل الإعلانية** إلى **خطة استشارية** واضحة، ثم
يتابع النتائج التي يُدخلها الفريق يدويًا. لا يطلق حملة ولا ينفق مالًا: هو
**يقترح**، والمالك **يعتمد**.

1. **استقبال المعلومات:** النشاط، الجمهور، الهدف (وعي / زيارات / رسائل / مبيعات…)،
   الميزانية بالدولار، والمدة.
2. **تحليل النشاط والجمهور:** قواعد حتمية للسوق العراقي، مع نصوص عربية مناسبة.
3. **اقتراح المنصات:** Meta وGoogle وTikTok حسب طبيعة النشاط، مع توزيع الميزانية
   بحيث مجموع الحصص = 100% ومجموع المبالغ = الميزانية الإجمالية.
4. **الخطة:** الهدف، الجمهور والجغرافيا، المنصات، المدة، الميزانية اليومية والإجمالية
   بالدولار، أفكار الإعلانات، النصوص، مؤشرات الأداء، وتوقعات **معلَّمة أنها تقديرات
   وليست نتائج مضمونة**.
5. **الحفظ كمسودة `DRAFT`.** لا يراها العميل.
6. **مراجعة المالك:** تعديل المسودة، إرسالها للمراجعة، ثم الاعتماد — قرار صريح من
   المالك وحده (`campaigns.plan.approve`).
7. **عرض العميل:** الخطة المعتمدة الخاصة به فقط، بلا ملاحظات داخلية وبلا مسودات.
8. **نتائج يدوية:** إنفاق، ظهور، نقرات، رسائل، طلبات — مصدر `MANUAL` فقط.
9. **تحليل:** حساب CTR / CPC / CPM / تكلفة الرسالة / CPA، واقتراح تحسينات.
10. **التقرير:** يُحفظ كمسودة في جدول `reports` القائم. نشره للعميل قرار منفصل.
    أي إعادة توزيع للميزانية تُفتح **نسخة DRAFT جديدة** دون تغيير الخطة المعتمدة.

## دورة الحياة والصلاحيات

```
مسودة DRAFT ──(إرسال للمراجعة)──► AWAITING_APPROVAL ──(اعتماد المالك)──► APPROVED
                     │                      │
                     └── تعديل = تبقى DRAFT └── تعديل خطة معتمدة = نسخة DRAFT جديدة
                                                                    (المعتمدة تبقى للعميل)
```

- **الاقتراح:** `proposeAdPlanDraft` في `src/lib/agents/specialists/ads.agent.ts`
  — بنية حتمية (منصات، ميزانيات، مؤشرات). الذكاء الاصطناعي إن وُجد يلمّع النصوص فقط.
- **الحفظ:** `createAdPlanForCustomer` / `saveAdPlanDraft` (`campaigns.manage`).
- **الإرسال للمراجعة:** `submitAdPlanForApproval` — تنبيه داخل التطبيق، **لا بريد**.
- **الاعتماد:** `approveAdPlan` — المالك فقط. لا إطلاق ولا إنفاق عند الاعتماد.
- **النتائج:** `recordAdPlanResult` — موظف، على خطة `APPROVED` فقط.
- **التحليل:** `analyzeAdPlan` — لا يغيّر الخطة المعتمدة.
- **الشريك** يُحضّر ويرسل ويدخل النتائج، **ولا يعتمد**.

## قاعدة الرؤية

| الحالة | ما يراه العميل |
|---|---|
| `DRAFT` / `AWAITING_APPROVAL` | لا شيء — نفس رسالة «غير موجود» |
| `APPROVED` | خطته فقط: المنصات، الميزانية، النصوص، التقديرات مع التنبيه، النتائج المُدخلة، التقارير المنشورة |
| تعديل بعد الاعتماد (نسخة `DRAFT`) | تظل النسخة **المعتمدة** حتى تُعتمد الجديدة |
| ملاحظة داخلية / `review_note` | لا تُرسل أبدًا |

## حدود الوكيل (استشاري فقط)

- لا اتصال بـ Meta Ads أو Google Ads أو TikTok Ads.
- لا إطلاق ولا إيقاف ولا تعديل حملات حقيقية.
- لا إنفاق أموال، ولا فواتير، ولا مدفوعات.
- لا بريد إلكتروني حقيقي.
- لا اختراع بيانات أداء ولا ضمان نتائج.
- لا اعتماد نيابة عن المالك.
- `POST /api/ads/[id]/launch` يُرفض دائمًا (412).

## الربط بالواجهات (API)

| الإجراء | المسار | من يستطيع |
|---|---|---|
| قائمة الخطط | `GET /api/ads` | الموظف: آخر نسخة لكل عائلة / العميل: المعتمدة فقط |
| إنشاء خطة (مسودة) | `POST /api/ads` | المالك/الشريك (`campaigns.manage`) |
| خطة واحدة | `GET /api/ads/[id]` | الموظف: كاملة / العميل: المعتمدة الخاصة به أو 404 |
| تعديل مسودة | `PATCH /api/ads/[id]` | المالك/الشريك — المعتمدة تصبح نسخة DRAFT جديدة |
| إرسال للمراجعة | `POST /api/ads/[id]/submit` | المالك/الشريك |
| **اعتماد** | `POST /api/ads/[id]/approve` | **المالك فقط** |
| إدخال نتائج يدوية | `POST /api/ads/[id]/results` | المالك/الشريك |
| تحليل واقتراح | `POST /api/ads/[id]/analyze` | المالك/الشريك |
| نشر تقرير للبوابة | `POST /api/ads/[id]/reports/[reportId]/publish` | المالك/الشريك — بلا بريد |
| إطلاق حملة | `POST /api/ads/[id]/launch` | **مرفوض دائمًا** |

- **لوحة الإدارة:** تبويب «الحملات» (`src/components/admin-ads.tsx`) عبر `/api/ads*`.
  يحتاج `DATABASE_DRIVER=postgres` + `DATABASE_URL` في الإنتاج (نفس نمط `/api/projects*`).
  بدون ذلك المسار يرد 503 وليس قائمة فارغة صامتة.
- **بوابة العميل:** تقرأ الخطة المعتمدة من `ofoq_client_dashboard()` (بعد 0012) عبر
  `/api/dashboard` — **بدون** `DATABASE_URL`. `GET /api/ads` إضافة اختيارية عند توفر القاعدة.
