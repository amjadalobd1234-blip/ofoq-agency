# نشر أفق على Supabase وVercel — دليل من الجوال

هذا الدليل يشرح إعداد قاعدة PostgreSQL على Supabase ثم نشر المشروع من GitHub إلى Vercel، ويمكن تنفيذ الخطوات من متصفح الهاتف. نفّذ النشر بعد دمج التغييرات إلى `main`.

> **مهم:** لم يكن في المستودع ملف `db/schema.ts`. اعتمدت مخططات SQLite الموجودة في `db/migrations/sqlite/` بوصفها المصدر الفعلي للجداول، وولّدت منها نسخ PostgreSQL. يحتوي مخطط التطبيق على **35 جدولاً**، ويصبح المجموع **36 جدولاً** مع جدول تتبّع الترحيلات `_migrations`.
>
> **حالة الواجهة:** المستودع الحالي لا يحتوي صفحة رئيسية (`src/app/page.tsx` أو `src/pages/index`). مسار الفحص `/api/health` موجود، لكن العنوان `/` سيعرض صفحة 404 من Next.js إلى أن تُبنى الواجهة. هذا التغيير يجهّز قاعدة البيانات والنشر، ولا ينشئ واجهة المنتج.

## ما الذي ستحتاجه؟

- حساب GitHub وصلاحية الوصول إلى `amjadalobd1234-blip/ofoq-agency`.
- حساب Supabase.
- حساب Vercel مرتبط بـ GitHub.
- اتصال إنترنت مستقر؛ الأفضل فتح لوحتي Supabase وVercel في متصفح الهاتف بوضع سطح المكتب عند الحاجة.

## 1. إنشاء مشروع Supabase

1. افتح [supabase.com](https://supabase.com) وسجّل الدخول.
2. أنشئ **New project**، واختر المؤسسة والمنطقة الأقرب لمستخدمي الموقع من المناطق المتاحة.
3. أنشئ كلمة مرور قوية لقاعدة البيانات واحفظها في مدير كلمات مرور. لا تضعها في GitHub أو في ملفات المشروع.
4. انتظر حتى تصبح قاعدة البيانات جاهزة.

### إنشاء الجداول

اختر **طريقة واحدة** من الطريقتين:

**الطريقة الأسهل من الجوال — SQL Editor**

1. بعد دمج التغييرات، افتح الملف `docs/setup/supabase-setup.sql` من المستودع على GitHub.
2. افتح الملف الخام (Raw)، وانسخ محتواه كاملاً.
3. في لوحة Supabase افتح **SQL Editor → New query**، والصق النص ثم اضغط **Run**.
4. يفترض أن تنتهي العملية من دون أخطاء. السكربت ينشئ 35 جدول تطبيق وجدول `_migrations`، والفهارس، ويفعّل Row Level Security، ثم يسجل أرقام الترحيلات وبصماتها حتى لا يعيد التطبيق إنشاء الجداول عند أول تشغيل للـ migrator.

السكربت قابل لإعادة التشغيل لإنشاء الجداول والفهارس الناقصة، لكنه **لا يعدّل** تعريف جدول موجود إذا غيّرت بنيته يدوياً. لا تعدّل الملف المولّد يدوياً؛ عدّل مخطط SQLite ثم أعد التوليد.

**طريقة سطر الأوامر — عند توفر كمبيوتر أو بيئة طرفية**

استخدم رابط قاعدة البيانات الخاص بالمشروع واضبط المتغيرات ثم نفّذ:

```bash
DATABASE_DRIVER=postgres DATABASE_URL='رابط-قاعدة-البيانات' npm run db:migrate
```

لا تنفّذ هذه الطريقة إذا لم تكن لديك بيئة طرفية. لا تحتاج إلى تشغيل الطريقتين معاً.

## 2. نسخ رابط الاتصال الآمن

1. في Supabase افتح **Connect** أو **Project Settings → Database**.
2. اختر رابط **Transaction pooler** عند النشر على Vercel، وانسخ URI كاملاً كما يظهر في اللوحة. عادة يستخدم منفذ `6543`؛ استخدم القيم التي تعرضها لوحة مشروعك ولا تركّب الرابط يدوياً.
3. احتفظ بالرابط سراً. قد يحتوي على كلمة مرور قاعدة البيانات. إذا احتوت كلمة المرور على رموز خاصة، استخدم رابط Supabase المنسوخ كما هو أو صيغة URL-encoded التي تعرضها اللوحة.

المشروع يتصل بـ PostgreSQL من الخادم عبر مكتبة `pg`، ولا يحتاج إلى Supabase anon key أو Supabase Auth كي يتصل بقاعدة البيانات. تسجيل الدخول في التطبيق يعتمد على نظام المستخدمين والجلسات الخاص بالمشروع.

## 3. استيراد المشروع في Vercel

1. افتح [vercel.com](https://vercel.com) وسجّل الدخول باستخدام GitHub.
2. اختر **Add New → Project**، ثم استورد `amjadalobd1234-blip/ofoq-agency`.
3. اترك إعداد **Framework Preset: Next.js**، وأمر البناء الافتراضي `npm run build`.
4. في **Environment Variables** أضف المتغيرات التالية. اختر **Production** على الأقل؛ وإذا أردت معاينات الفروع، أضف قيماً مناسبة إلى **Preview** أيضاً.

| المتغير | القيمة |
|---|---|
| `DATABASE_DRIVER` | `postgres` |
| `DATABASE_URL` | رابط Transaction pooler المنسوخ من Supabase |
| `APP_URL` | عنوان النشر الفعلي، مثل `https://اسم-المشروع.vercel.app` (من دون `/` في النهاية) |
| `APP_DOMAIN` | اسم النطاق فقط، مثل `اسم-المشروع.vercel.app` (من دون `https://`) |
| `AUTH_SECRET` | سر عشوائي قوي بطول 32 محرفاً على الأقل؛ من الهاتف استخدم مولّد كلمات مرور موثوقاً واجعل الطول 48 محرفاً أو أكثر، أو أنشئه على كمبيوتر بـ `openssl rand -base64 48` |
| `AUTH_COOKIE_SECURE` | `true` |
| `AUTH_TRUSTED_ORIGINS` | أصل الموقع نفسه، مثل `https://اسم-المشروع.vercel.app`، من دون `/` في النهاية |
| `APP_ENCRYPTION_KEY` | موصى به للتكاملات التي تخزن رموزاً مشفرة؛ أنشئه على كمبيوتر بـ `openssl rand -base64 32` واحفظه سراً |
| `SEED_DEMO_DATA` | `false` |

تضيف Vercel `NODE_ENV=production` تلقائياً. لا تضف `NEXT_PUBLIC_` إلى `DATABASE_URL` أو إلى أي سر، ولا تضع الأسرار في الشيفرة أو في GitHub. إذا غيّرت عنوان النشر أو أضفت نطاقاً مخصصاً، حدّث `APP_URL` و`APP_DOMAIN` و`AUTH_TRUSTED_ORIGINS` ثم أعد النشر.

المتغيرات الاختيارية مثل مزوّد الذكاء الاصطناعي والبريد وGoogle وWhatsApp يمكن تركها غير مضبوطة؛ التكاملات تبدأ معطّلة افتراضياً. لا تفعّل تكاملاً قبل إضافة مفاتيحه الصحيحة إلى إعدادات Vercel.

5. اضغط **Deploy** وانتظر انتهاء التثبيت والبناء. بعد أي تعديل لمتغيرات البيئة، أعد النشر كي يقرأ التطبيق القيم الجديدة.

## 4. التحقق من النشر

افتح هذا العنوان بعد ظهور رابط النشر:

```text
https://اسم-المشروع.vercel.app/api/health
```

عند نجاح اتصال قاعدة البيانات تكون الاستجابة `200` وبصيغة قريبة من:

```json
{"status":"ok","database":"ok","latencyMs":12}
```

إذا أعاد الفحص `503`، راجع رابط Supabase وكلمة المرور، وتأكد من استخدام رابط الخادم (Transaction pooler) في متغير `DATABASE_URL`، ثم راجع **Vercel → Deployments → Build/Runtime Logs**. لا يعرض مسار الفحص تفاصيل الاتصال أو الأسرار.

## ملاحظات أمان وتشغيل

- جداول `public` محمية بـ **RLS** ولا توجد سياسات وصول للمتصفح. اتصل من خادم التطبيق باستخدام `DATABASE_URL` محفوظ في Vercel فقط؛ لا تستخدم بيانات قاعدة البيانات في كود المتصفح. إذا أردت استخدام Supabase Data API مباشرة، صمّم سياسات RLS واختبرها أولاً.
- عند تشغيل `npm run db:migrate` مباشرة، ينشئ الـ migrator جدول `_migrations` ويطبق الملفات بالترتيب. سكربت Supabase اليدوي يسجل بصمات الملفات نفسها حتى يستطيع الـ migrator متابعة التغييرات اللاحقة من دون إعادة إنشاء الجداول الأساسية.
- لإعادة توليد الملفات بعد تعديل مخطط SQLite شغّل `npm run db:generate-postgres`. ينتج هذا الأمر `db/migrations/postgres/` و`docs/setup/supabase-setup.sql`.
- ملفات Supabase تجهّز **المخطط والفهارس** فقط؛ لا تنشئ بيانات تجريبية. لا تشغّل `npm run db:seed` على قاعدة الإنتاج.
- هذا الدليل يضبط PostgreSQL فقط. تخزين الملفات لدى مزوّد خارجي أو إعداد نطاق مخصص أو تفعيل مزوّدات الدفع والبريد خطوات مستقلة.
